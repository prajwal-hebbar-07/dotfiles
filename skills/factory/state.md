# Factory run state

Everything the factory needs between sessions lives in `.factory/` in the
target repo (kept out of git by `.git/info/exclude`) and in GitHub labels.
Nothing depends on an earlier chat. All writes go through
`~/.omp/agent/skills/factory/scripts/factory-state` (run from the repo root;
exit 0 ok, 1 check failed, 2 usage/environment error).

## state.json (version 1)

```json
{
  "version": 1,
  "mode": "app",
  "guard": true,
  "stage": "requirements",
  "feature": null,
  "gates": { "requirements": {"file": "docs/factory/REQUIREMENTS.md", "sha256": "…", "approvedAt": "ISO-8601"} },
  "stop": null,
  "nextAction": "…",
  "blockedOnUser": false,
  "guardStage": { "exitMet": false, "reason": "" },
  "issues": { "12": {"status": "factory:building", "branch": "factory/12-slug", "attempts": {}} },
  "prApprovals": { "factory/12-slug": "<head sha>" },
  "boardMode": null
}
```

| Key | Meaning |
| --- | --- |
| `mode` | `app` (full factory) or `feature` (`/skill:feature`) |
| `guard` | hooks enforce only while true; `factory-state done` sets it false |
| `stage` | `requirements`, `stack`, `architecture`, `issues`, `build`, `land`, `feature` |
| `feature` | feature slug, feature mode only |
| `gates` | one stamp per approved doc: file, sha256 at approval, time. Names: `requirements`, `stack`, `architecture`, `issues`, `brief`. The guard blocks edits to a stamped file; `reopen` removes the stamp |
| `stop` | `S1`..`S5` while parked at a stop, else null |
| `nextAction` | one sentence: what `/skill:factory` does next |
| `blockedOnUser` | true while waiting for the user; lets the session end |
| `unattended` | true only during unattended runs (`factory-build`, feature steps 5–9), set by `factory-state unattended on "<reason>"`. The stage guard blocks ending the session only while this is true; interactive stages leave it false so turns end normally while the user answers. `stop` and `done` clear it |
| `guardStage` | stage exit predicate, set by `factory-state exit met\|unmet "<reason>"` from real checks, never from an agent's claim |
| `issues` | per issue: GitHub label status, branch, failure attempts by test id + error class |
| `prApprovals` | branch to the head SHA the user approved in "Raise PR?"; the hook allows `pr_create` only for the current HEAD |
| `boardMode` | `whole-app` or `feature-by-feature` |

PR approval is not a doc gate; it is `prApprovals`.

## ledger.tsv

Tab-separated, header row, one row per event:

`ts	issue	stage	step	event	agent	model	sha	result	evidence`

`event` is `start`, `done`, or `verdict`. A step writes `start` before acting
and `done` only after its own check passes, so a `start` with no later `done`
(same issue, stage, step) is interrupted work: `factory-state ledger open`
lists them. Feature mode uses the slug as `issue`. `factory-state budget
<issue>` sums start-to-done spans and counts helper-agent runs; it exits 1 at
3600 s or 40 runs, and the issue then gets `factory:needs-human`.

## Labels and branches

`factory:queued`, `factory:building`, `factory:review`, `factory:qa`,
`factory:ui`, `factory:pr-ready`, `factory:needs-human`, plus `sec:boundary`
and `ui`. Branches: app mode `factory/<issue>-<slug>`; feature mode
`feature/<slug>`. Every factory comment starts `> Generated by the factory.`
and carries a hidden `<!-- factory:step=<step> -->` marker, so a resumed step
finds its own comment, commit, or PR and never creates a second.

## Stops

| Stop | After |
| --- | --- |
| S1 | REQUIREMENTS.md approved |
| S2 | STACK.md approved |
| S3 | ARCHITECTURE.md (+ CONSTRAINTS, design brief) approved |
| S4 | Issues published to the board |
| S5 | Each issue's "Raise PR?" answered; in whole-app mode, each frontier wave |

At a stop: commit the stage's artifacts through `commit`, write state
(`factory-state stop S<n> "<next action>"`), end with the printed stop line.

## Resume protocol

Find the last `done` and any open `start` in the ledger. Uncommitted changes
from the interrupted step are kept if that step's test now passes, else
stashed to `wip/<issue>/<step>` and the step restarts clean from its brief,
not from memory. Re-check the last `done` claim once before continuing.
Every step first checks whether it is already done (branch at the expected
SHA, PR open, comment marker present).

## Retry by failure mode

Two retries at most, then the step is marked `factory:needs-human` with its
evidence.

| Signal | Action |
| --- | --- |
| Context overflow | omp compaction runs; a second overflow in the same step splits the step |
| Helper agent returns nothing | check the branch and ledger without reviving it; respawn once with the same brief |
| Short rate limit (429, quota not exhausted) | omp retries the same model with backoff (`retry.maxRetries`, 10) |
| Account quota out (10% reserve) | handled by omp, not retried here |
| The same tool error repeats | retry once on the step's fallback model (GPT steps: Opus 5.5 · high; Claude steps: Opus ↔ Sonnet 5.5 · high) |

Failure attempts per issue are three, each different (builder, unstick
advisor, fresh builder); there is no fourth.
