# PR body template

Fill every section from facts: the issue, the diff, `.factory/ledger.tsv`, the
CI run, `qa-evidence/<issue>/<sha>/`. Short sentences, `##` headings, drop a
section only where noted. Title: Conventional Commits `type(scope): subject`,
imperative, no trailing period. Open ready, never draft.

Sources: sections Why to Verification follow pstack `opening-a-pr`
(cursor/plugins, `poteto-mode/playbooks/opening-a-pr.md`); Merge Danger follows
mattpocock `pr` (itself credited to Dex Horthy's `show-me`). Manual check is the
factory's own.

```markdown
> Generated by the factory.
<!-- factory:step=pr -->

## Why
<problem and approach, 1-3 short sentences. No SHAs or rebase history.>

## What changed
<1-3 bullets. Name a symbol or path only when it carries the change.>

## Scope
<1-3 items: what it covers, what it leaves out and which issue has that.>

## Tradeoffs
<only rejected alternatives a reviewer would ask about. Drop if none.>

## Blast Radius
<1-2 sentences: who or what it touches and why that is safe or risky.>

## Verification
- Local: `check:full` <pass>, head <short sha>.
- CI: <run link> green on <short sha>.
- Tests: <acceptance criterion -> test, level, 3/3 runs, mutation score>.
- QA: <n>/<n> scenarios PASS; evidence <link to qa-evidence/<issue>/<sha>/>.
- Reviews at patch-id <id>: code <P-level summary>, spec <verdict>, tests <verdict>,
  QA review <verdict>, UI review <verdict or n/a>, security <verdict or n/a>.
- Fallback models: <list each verdict given on a fallback model with agent and
  model, or "none">.
- Declined / needs-human items: <none or list>.

## Merge Danger
**Door:** <one-way or two-way>
<one line why: migration, deleted data, published API, config format = one-way>

**Blast Radius:** <one word>

## Manual check
1. Start: `<command that starts the app from empty data>`.
2. <what to click or run> -> you should see <result>.
3. <next journey step> -> <result>.
<one short block per QA journey; the factory's browser tests ran first, this
is your pass.>

Closes #<issue>
```

Rules: Verification bullets are real runs with outcomes, copied from the
ledger rows, never from memory. The Summary diagram and Evidence
before/after from `pr` are optional: add a screenshot link only when the
change is visual. Whole-app wave PRs list each issue as `Closes #N` only when
the base is main; for a wave-branch base write `Refs #N` (the factory
closes the issue when the code reaches main, `skill://factory-land`).
